# ファイル分割 {#ch-splitting}

## 1ファイル1章にする理由 {#sec-splitting-why}

無難だからではありません。**制約のうち4つが、1ファイル1章にした瞬間に要求そのものに変わる**からです。

| 制約 | 1ファイル1章にすると |
| --- | --- |
| ファイル境界で必ず改ページされる | 章は改ページで始めたい → 要求と一致 |
| 文書カウンターがリセットされる | 節・定理・図は章ごとにリセットしたい → 要求と一致 |
| `string-set` がリセットされる | 柱は章ごとに変わってほしい → 無害になる |
| 脚注番号がリセットされる | 章ごとに 1 から振るなら → 要求と一致 |

残るのは章番号だけで、それだけをページ制御カウンターに逃がせば済みます。

逆に「1章を複数ファイルに」は、この3つに同時に引っかかるので成立しません。

<div class="thm" id="thm-split-rule">
<p>分割の単位は、<strong>改ページしてよい単位</strong>に一致させる。</p>
</div>

## 洗い出した制約 {#sec-splitting-constraints}

| | 制約 |
| --- | --- |
| C-1 | ファイル境界では必ず改ページされる。`break-before: avoid` でも避けようがない |
| C-2 | 文書カウンターはファイル境界でリセットされる |
| C-3 | `string-set`（名前付き文字列）はファイル境界でリセットされる |
| C-4 | 文書ローカルの `@page` 規則は、その文書にしか効かない |
| C-5 | ページグループはファイル境界で必ず切れる |
| C-6 | ファイル境界に入る白紙ページは完全な白紙で、`@page :blank` が効かない |
| C-7 | 文書の途中で `page` の名前を変えると、そこで改ページされる |
| C-8 | `@page :first` は出版物の最初の1ページだけ。各ファイルの1ページ目は `:nth(1)` |
| C-9 | 脚注番号はファイル境界でリセットされる |
| C-10 | `entry` に無いファイルは無警告で出版物から落ちる |
| C-11 | 出版物の順序を決めるのは `entry` 配列だけ |

C-6 は分割と引き換えの制約です。「このページは白紙です」を刷りたいなら、章を1ファイルにまとめるしかありません。

C-7 のせいで、`page:` は**文書ごと**（`body`）に付けます。文書の途中の要素に付けると、そこで改ページされます。

C-4 には良い面もあります。**ファイルごとに判型を変えることができます**[^size]。

[^size]: 逆に、判型を書き忘れたファイルだけ別の判型で出ます。表紙がその代表例です。

## 柱はファイルごとに設定し直される {#sec-splitting-runhead}

`string-set` はファイルをまたぎません。1ファイル1章なら、各ファイルの `h1` で設定し直されるので自動的に成立します。

```css
body.chapter section.level1 > h1 { string-set: runhead content(text); }
@page chap:left { --vs-page--mbox-top-left-content: '第' counter(chapter) '章　' string(runhead); }
```

このページの左上（または右上）に出ているのがそれです。

<div class="rem">
<p>柱を <code>position: running()</code> で組み、その中に<strong>前方参照</strong>を
置いてはいけません。最初のページでしか解決されず、2ページ目以降は
<code>??</code> のまま残ります。柱は <code>string-set</code> で組みます。</p>
</div>

## 部でのグループ化 {#sec-splitting-part}

部は章と同じくページ制御カウンターで採番します。**部をまたいで通し番号にするか、部ごとに振り直すかは1行の違いです。**

```css
@page part:nth(1 of part) { counter-increment: part; }
/* 部ごとに章番号を振り直すなら ↓ */
@page part:nth(1 of part) { counter-increment: part; counter-reset: chapter; }
```

この本は前者です。部が変わってもこの章（[](#ch-splitting){.ref-ch}）の番号が前の部から続いているのが、その結果です。
